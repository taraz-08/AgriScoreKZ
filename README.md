# AgriScore KZ

**Платформа скоринга субсидий на основе Explainable AI / ML**

Министерство сельского хозяйства РК · AI inDrive Hackathon 2026 · Кейс 2

---

## Проблема

В Казахстане государственные сельскохозяйственные субсидии распределяются по принципу **«кто первый подал — тот и получил»**. Реальная эффективность хозяйства, история освоения субсидий и потенциал роста не учитываются. В результате:

- Эффективные хозяйства проигрывают из-за опоздания с подачей заявки
- Недобросовестные получатели субсидий претендуют повторно
- Процесс принятия решений непрозрачен, нагрузка на комиссию высокая

**AgriScore KZ** — формирует объективный рейтинг на основе данных и ML. Финальное решение принимает человек (комиссия) — AI только рекомендует.

## ML Pipeline

```
Загрузка данных (Excel/CSV или импорт с subsidy.plem.kz)
    → Предобработка + нормализация
    → 4-факторный скоринг (F1–F4, 0–90 баллов)
    → Обнаружение аномалий (9 правил)
    → Кластеризация K-means++ (4 кластера, 6 признаков)
    → Proxy Logistic Regression (вероятность успешного освоения)
    → Гибридный балл: 50% ML + 30% бизнес-правила + 20% риск
    → SHAP-style объяснение факторов
    → Шортлист + Решение комиссии → Журнал аудита
```

---

## Факторы скоринга (F1–F4)

| Фактор | Макс. балл | Описание |
|--------|-----------|----------|
| **F1** — Поголовье / Масштаб | 30 | Sigmoid: выше медианы по региону = 15 баллов |
| **F2** — Приоритет направления | 25 | По государственным приоритетам (мясо/молоко/шерсть и др.) |
| **F3** — Категория субсидии | 20 | Тарификация по категории субсидии |
| **F4** — Региональное сравнение | 15 | Sigmoid: выше/ниже среднего по району |

**Формула гибридного балла:**
```
hybridScore = 0.5 × mlScore + 0.3 × businessScore + 0.2 × riskScore
riskPenalty = min(40, errCount×8 + warnCount×3)
```

**Матрица решений:**

| Балл | Статус | Рекомендация |
|------|--------|--------------|
| 70–100 | Рекомендован | Добавить в шортлист |
| 50–69 | На проверке | Рассмотрение комиссией |
| 0–49 | Не рекомендован | Отказ |

## ML-возможности

### Кластеризация K-means++ (Pure JS, без зависимостей)
- 6 признаков: `totalScore`, `hcRatio`, `successProb`, `subsCategory`, `dirPriority`, `riskScore`
- Признак `originalStatus` исключён для предотвращения утечки данных
- 4 кластера с автоматическими метками по среднему баллу:
  - 🌟 **Высокоэффективные** — высокий балл, хорошая история освоения
  - 📊 **Стабильные** — средний балл, стабильное хозяйство
  - 🌱 **Потенциал роста** — низкий балл, но достаточные ресурсы
  - ⚠️ **Рисковые** — признаки аномалий, требуют проверки

### Proxy Logistic Regression
```
z = 3.5×score + 1.4×dirP + 0.8×catP + 0.7×hcRatio
  + 2.1×executed + 0.9×approved − 1.5×rejected + 0.4×prevSub − 4.1
```
- Откалибровано на 36 651 реальных заявке с subsidy.plem.kz
- Результат: вероятность успешного освоения субсидии (%)

### SHAP-style объяснение факторов
- Отклонение каждого фактора от среднего по пулу
- Положительный / отрицательный вклад с иконкой и значением %
- Отображается на странице детали заявки (реальные значения F1–F4)

### Обнаружение аномалий (9 правил)
- Несоответствие балла и продуктивности
- Статистический выброс (на основе IQR)
- Аномальное соотношение суммы субсидии к поголовью
- Дубликаты по ИИН
- Дисбаланс земля/техника

### Метрики модели
- Precision / Recall / F1-score (по реальному `originalStatus`)
- Матрица ошибок (TP / FP / TN / FN)
- Столбчатая диаграмма важности признаков (веса F1–F4)

## Аутентификация

### Логин / Пароль
Стандартная форма входа.

### ЭЦП (NCALayer)
Вход с помощью электронной цифровой подписи РК:
1. Установите и запустите [NCALayer](https://pki.gov.kz/ncalayer/)
2. Нажмите «Войти через ЭЦП» → WebSocket-соединение с `wss://127.0.0.1:13579/`
3. Выберите ключ типа AUTH → ИИН и ФИО определяются автоматически
4. Известный пользователь → его роль; новый ИИН → роль **Оператор**

| Логин | Пароль | Роль |
|-------|--------|------|
| `admin` | `AgriScore2025!` | Администратор |
| `analyst` | `Analyst2025!` | Аналитик |
| `operator` | `Operator2025!` | Оператор |

| Технология | Назначение |

## Быстрый старт

```bash
# 1. Клонировать репозиторий
git clone https://github.com/taraz-08/AgriScoreKZ.git
cd AgriScoreKZ

# 2. Создать .env (необязательно — без него работает demo-режим)
cp .env.example .env
# Заполните GEMINI_API_KEY

# 3. Запустить сервер
node server.js

# 4. Открыть в браузере
# http://localhost:3000
```

### Пример .env

```env
GEMINI_API_KEY=your_key_here

ADMIN_LOGIN=admin
ADMIN_PASSWORD=AgriScore2025!
USER1_LOGIN=analyst
USER1_PASSWORD=Analyst2025!
USER2_LOGIN=operator
USER2_PASSWORD=Operator2025!
```

Если Gemini API ключ не указан — автоматически включается demo-режим с заготовленными ответами.

## Безопасность

- API-ключ хранится в `.env` — только на сервере, в браузер не передаётся
- `.env` в `.gitignore` — не попадает в репозиторий
- Защита от path traversal при раздаче статики
- Security headers: `X-Content-Type-Options`, `X-Frame-Options`
- ИИН из ЭЦП валидируется на сервере (формат: ровно 12 цифр)

**Ключевые принципы:**
